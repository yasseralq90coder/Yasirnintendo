# خادم Nintendo Store الخاص

الواجهة منشورة على GitHub Pages، لكن Pages لا ينفذ هذا الخادم. هذا تنفيذ Node.js 22+ دون حزم خارجية. الرموز لا تُنشر إلى GitHub، ولا تُحفظ داخل localStorage أو Backup. لا يوجد خادم حي مُعدّ تلقائيًا.

## تشغيل محلي على Windows

من مجلد المستودع في PowerShell:

```powershell
$env:BRIDGE_KEY = node -e "process.stdout.write(require('crypto').randomBytes(32).toString('hex'))"
$env:VAULT_KEY = node -e "process.stdout.write(require('crypto').randomBytes(32).toString('base64'))"
$env:VAULT_PATH = "$env:LOCALAPPDATA\YasirNintendo\vault.json"
npm run bridge
```

احتفظ بقيمتي BRIDGE_KEY وVAULT_KEY في مدير كلمات المرور قبل إغلاق النافذة. عند التشغيل التالي أدخلهما في متغيرات البيئة نفسها. لا تُنشئ VAULT_KEY جديدًا فوق ملف مشفّر موجود؛ المفتاح الأصلي مطلوب لفتحه. BRIDGE_KEY مفتاح اتصال خاص بهذا الخادم وليس رمز Nintendo. لنسخه محليًا في PowerShell استخدم `$env:BRIDGE_KEY | Set-Clipboard`، ولا ترسله في المحادثة أو المستودع.

## Linux / macOS

```sh
export BRIDGE_KEY="$(node -e "process.stdout.write(require('crypto').randomBytes(32).toString('hex'))")"
export VAULT_KEY="$(node -e "process.stdout.write(require('crypto').randomBytes(32).toString('base64'))")"
export VAULT_PATH="$PWD/server/private/vault.json"
npm run bridge
```

احفظ الأسرار في مدير كلمات المرور، وأعد تمرير نفس VAULT_KEY عند التشغيل التالي. `server/private/` مستثنى من Git.

## من الموقع

1. افتح الموقع على نفس الكمبيوتر → الإعدادات → ربط Nintendo Store.
2. عنوان الخادم `http://127.0.0.1:8787`، وأدخل BRIDGE_KEY ثم «اتصال بالخادم». قد يطلب المتصفح إذن الوصول إلى الشبكة المحلية؛ الدعم يعتمد على المتصفح. مفتاح الربط لا يُخزن في المتصفح.
3. اضغط «ربط حساب Nintendo»، وافتح صفحة Nintendo وسجّل الدخول هناك.
4. عند زر Select this person انسخ عنوان الرابط (نقرة يمين → نسخ الرابط)، والصقه في الحقل الخاص داخل الموقع. صالح لمحاولة واحدة خلال 10 دقائق. لا تلصقه في المحادثة.
5. اضغط «إتمام الربط»، ثم «تحديث الآن». يستمر الجلب في الخادم ويمكن متابعة حالته. يستورد الموقع آخر Snapshot ناجح تلقائيًا عند انتهاء الجلب، أو بزر «جلب آخر بيانات ناجحة».
6. راجع فئة اللعبة وملكية فيزكال/رقمي، لأن سجل Nintendo لا يحدد ملكيتها. النسخ والمنصات لا تندمج بالاسم؛ لا يجري دمج اللعبة اليدوية تلقائيًا مع المستوردة.

رمز الجلسة يُحفظ AES-256-GCM بملف صلاحياته 0600. رمز الوصول في الذاكرة ويُجدد قبل انتهائه. لا تُسجل رموز أو أجسام الطلبات أو روابط callback. ربط حساب جديد يتطلب فصل الحالي، ويعطي مساحة هوية جديدة دون دمج الحسابات.

## الجوال والاستضافة

`127.0.0.1` على الجوال يعني الجوال نفسه، وليس الكمبيوتر. يمكن نقل Backup لعرض البيانات على الجوال دون خادم. لتحديث مباشر من الجوال تحتاج خادمًا خاصًا دائمًا خلف HTTPS وتخزين دائم للملف المشفر.

الخادم يستمع على `127.0.0.1` فقط. على VPS ضع reverse proxy مثل Caddy/Nginx أمام المنفذ 8787، مع شهادة HTTPS موثوقة. استعمل `BRIDGE_KEY` و`VAULT_KEY` كأسرار خدمة، و`VAULT_PATH` على قرص دائم، و`APP_ORIGIN=https://yasseralq90coder.github.io`. يجب ألا يسجل reverse proxy ترويسة Authorization أو أجسام الطلبات. لا تفتح منفذ Node للعامة دون HTTPS. لا تدعم هذه النسخة أكثر من عملية Node واحدة على نفس ملف الخزنة.

الدعم المباشر للمتصفح يحتاج CORS؛ الخادم يقبل أصل التطبيق المحدد فقط ويطلب مفتاح اتصال عشوائيًا في كل طلب. الواجهة تسمح بأصل HTTPS لخادمك أو localhost بالمنفذ 8787. لا تربطها بخادم لا تثق به لأنه سيستقبل تفويض حسابك.

## سلوك المزامنة

- اجلب القائمة الكاملة، ثم تفاصيل العناوين الجديدة/المتغيرة/ناقصة التاريخ. مراجعة أسبوعية كاملة، وزر للمراجعة الكاملة يدويًا.
- كل 6 ساعات أثناء بقاء عملية الخادم قيد التشغيل. زر التحديث محدود بمرة في الدقيقة، والعمليات المتزامنة تشترك في جلب واحد.
- الطلبات متتابعة بفاصل 350ms. `429` يحترم Retry-After حتى 5 دقائق مع إعادة محاولات محدودة، ثم يحفظ آخر نجاح ويظهر خطأ. `401/403` يجرب id_token مرة ثم يجدد رمز الوصول.
- تفاصيل الأيام تجرب `limit=16&offset=0,16,...` وفق وصف المستخدم. هذا المسار لم يكن منفذًا في playhistory.go الذي تمت مراجعته؛ اختبر شكل الاستجابة الفعلي عند أول ربط. لا تعتبر صفحة فاشلة نهاية السجل.
- عند فشل صفحة يحتفظ السجل اليومي السابق كاملًا ويُعلّم ناقصًا، بدل اعتماد تاريخ جزئي. نجاح الجلب الكامل يستبدل الأيام ويلتقط التصحيحات والحذف. اليوم الحالي قابل للتحديث.
- وقت Nintendo الإجمالي يستبدل نفسه ولا يُجمع مع الأيام أو الجلسات اليدوية. التقويم يستخدم مجموع Nintendo لليوم عند توفره بدل الجلسات اليدوية لنفس العنوان واليوم. يوم المصدر يبقى كما هو، دون اختلاق ساعة جلسة.
- الصفوف مفتاحها هوية حساب محلية + titleId + platform + date. HAC → Switch وBEE → Switch 2. منصات 3DS/Wii U غير مدعومة في واجهة هذا المشروع وتُستبعد من الجلب الحالي.
- حاوية NSO لعبة/تطبيق واحد؛ لا تستنتج الكلاسيكية داخله. لا تدمج النسخ المطورة بالاسم.
- الخطأ في القائمة أو رجوع قائمة فارغة غير متوقعة لا يمسح آخر بيانات. Backup يشمل بيانات اللعب فقط، لا الرموز. فصل الربط يمسح الخزنة الخلفية وتبقى النسخة المحلية.

## التحقق

```sh
npm test
npm run check
```

اختبارات للاستبدال دون تضخيم، فصل المنصات، صفحات الأيام والفشل، PKCE والتشفير، 429 وبديل id_token. الاختبارات تستخدم بيانات محاكاة؛ لا تثبت نجاح اتصال حساب فعلي أو أن Nintendo ستستمر بقبول العميل غير الرسمي.

مرجع البروتوكول: https://github.com/robtme/nintendo-go — تمت مراجعة auth.go وnintendo.go وplayhistory.go. لم تتوفر ملفات C# الموجودة على جهاز المستخدم في هذه الجلسة. الواجهة غير رسمية وقد تتغير، واستخدام العميل قد يخالف شروط Nintendo. لا يُدّعى دقة 100٪ أو شمول كامل الملكية.
